# Feature Specification: HelloAgentsLLM 适应性模型调用中枢

**Feature Branch**: `001-helloagents-llm-hub`  
**Created**: 2026-03-21  
**Status**: Draft  
**Input**: User description: "7.2 HelloAgentsLLM 扩展：多提供商（OpenAI、ModelScope、智谱 AI 等）、本地高性能推理（VLLM、Ollama，作为 Transformers 本地方案的生产级补充）、环境自动检测与统一凭证解析；支持通过继承扩展新 provider，避免修改上游库源码。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 多提供商统一配置与切换 (Priority: P1)

作为在本仓库中开发智能体示例的开发者，我希望在代码里用同一个客户端类型、通过显式指定「服务商」或约定式环境变量，就能连接 OpenAI、ModelScope、智谱等不同云端服务商，而不必每次查文档去改默认地址和密钥变量名。

**Why this priority**: 解除与单一供应商的隐性绑定，是后续本地部署与自动检测的前提，直接降低接入成本。

**Independent Test**: 在仅配置某一服务商对应的环境变量（或显式传入等价信息）且指定该服务商时，能够成功完成一次对话请求并得到流式或非流式回复；切换到另一服务商时无需改业务调用代码，仅需改配置或 `provider` 参数。

**Acceptance Scenarios**:

1. **Given** 已配置 OpenAI 兼容云端服务的密钥与可选基地址，**When** 开发者指定该云端服务商并发起对话，**Then** 请求发往解析后的服务端点且返回有效模型输出。
2. **Given** 已按约定配置 ModelScope 的凭证，**When** 开发者指定 ModelScope 服务商，**Then** 使用该平台默认推理基地址与推荐默认模型（可被入参或环境覆盖）。
3. **Given** 已按约定配置智谱 AI 的凭证，**When** 开发者指定智谱服务商，**Then** 使用与该服务商文档一致的默认基地址与解析规则。
4. **Given** 开发者选择在应用代码中继承基础客户端并实现自定义分支，**When** 传入自定义 `provider` 标识，**Then** 走子类逻辑；其他 `provider` 仍走基类行为，无需 fork 上游库源码。

---

### User Story 2 - 本地高性能推理接入 (Priority: P2)

作为需要在本地或内网跑模型的开发者，我希望把已部署的、对外暴露「与 OpenAI Chat Completions 兼容」的 HTTP 服务的推理后端（文档中强调的 VLLM 与 Ollama 两类场景）接到同一客户端上，以便在隐私与成本敏感场景下与云端切换时保持调用方式一致。

**Why this priority**: 在 P1 统一接口之上，补齐生产级本地推理路径，与仅用于实验的 Transformers 直载方案形成互补。

**Independent Test**: 在本地已启动文档所述端口的兼容服务时，通过指定对应服务商或等价基地址，能够完成与 User Story 1 相同形态的 `think` 调用并得到流式输出。

**Acceptance Scenarios**:

1. **Given** 本地 VLLM 兼容服务在约定主机与端口可用，**When** 开发者配置与启动命令一致的模型标识与基地址，**Then** 客户端成功完成对话且模型名与服务端一致。
2. **Given** 本地 Ollama 兼容服务在约定端口可用，**When** 开发者配置与 `ollama run` 一致的模型名与基地址，**Then** 客户端成功完成对话。
3. **Given** 本地服务不要求真实 API 密钥，**When** 开发者传入占位非空密钥或环境中等价约定，**Then** 不因「密钥格式」误拒合理配置。

---

### User Story 3 - 环境自动检测与凭证解析 (Priority: P3)

作为希望「约定优于配置」的开发者，我只想在环境中设置通用或服务商专属的变量（如基地址、模型 ID、密钥），**When** 不显式传入服务商，**Then** 客户端按文档约定的优先级推断服务商并补全默认基地址与凭证来源，使现有脚本可零改或极少改动。

**Why this priority**: 在 P1/P2 能力具备后，进一步减少配置错误与文档翻阅成本。

**Independent Test**: 仅设置 `.env` 中基地址（含本地端口特征）与模型 ID、不显式传 `provider`，能够推断为预期服务商并完成一次成功调用；多信号并存时行为符合规定的优先级说明。

**Acceptance Scenarios**:

1. **Given** 环境中存在某一服务商专属密钥变量（优先级高于通用变量），**When** 使用默认自动模式实例化客户端，**Then** 推断为该服务商并解析对应默认基地址（若未显式提供）。
2. **Given** 未设置专属密钥但设置了通用基地址，**When** 基地址主机名或端口符合文档中的本地或云端特征，**Then** 推断为对应服务商或泛本地类别。
3. **Given** 前两类信息不足但存在通用密钥，**When** 密钥具有文档约定的可区分前缀或模式，**Then** 可作为较低优先级辅助推断；若仍无法唯一确定，**Then** 回退到安全、可预测的默认（如保持通用自动配置或明确报错，与实现文档一致）。
4. **Given** 推断完成，**When** 调用对话接口，**Then** 用户可见日志或诊断信息中能确认最终采用的服务商标签（便于排错）。

---

### Edge Cases

- 多个服务商的环境变量同时存在时，必须按规范优先级唯一确定，避免随机或实现依赖顺序。
- 基地址指向本地但端口不在文档列举范围时，应归类为泛「本地/自定义」并仍要求有效模型与可达服务，错误信息应指向配置而非笼统失败。
- 缺少必需凭证或模型 ID 时，应在初始化或首次调用前给出明确错误，不静默连接错误端点。
- 流式与非流式两种调用路径在各类服务商下行为一致；网络超时可配置。
- 自动检测误判时，用户可通过显式 `provider` 覆盖推断结果。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 客户端 MUST 支持至少以下服务商标签的显式选择：OpenAI、ModelScope、智谱 AI、VLLM（本地兼容服务）、Ollama（本地兼容服务），以及「自动」模式。
- **FR-002**: 在「自动」模式下，客户端 MUST 按文档约定顺序组合：专属环境变量 → 通用基地址解析（域名与端口启发）→ 通用密钥格式辅助 → 最终默认策略。
- **FR-003**: 对每个已支持的服务商，客户端 MUST 能解析默认基地址与密钥来源（含专属变量名与通用变量回退），并允许用户用显式参数覆盖环境。
- **FR-004**: 客户端 MUST 继续暴露与现有一致的对话调用入口（如 `think`），且默认支持流式输出；非流式路径 MUST 仍可用。
- **FR-005**: 客户端 MUST 允许应用侧通过继承基类、在子类中拦截特定 `provider` 并 `super()` 回退的方式扩展新服务商，且不依赖修改已安装包内源码。
- **FR-006**: 客户端 MUST 在自动推断或显式选择后，向用户或日志提供可观测的最终服务商与解析后的连接目标（脱敏处理密钥）。
- **FR-007**: 当配置不完整或冲突导致无法安全连接时，客户端 MUST 失败并给出可操作的错误说明（缺少哪类配置、如何设置环境变量等）。

### Assumptions

- 各服务商与本地后端均通过「OpenAI Chat Completions 兼容」的 HTTP 接口访问；不强制在本规格内实现模型权重加载或 GPU 调度。
- 项目继续以环境文件与进程环境变量作为配置主渠道；示例脚本与教材风格保持一致。
- 智谱、ModelScope 等的默认基地址与变量命名以各官方公开文档为准，本功能按教材给定缺省值实现，可通过环境覆盖。

### Key Entities *(include if feature involves data)*

- **服务商配置（Provider Configuration）**: 逻辑标签（如 openai、modelscope、zhipu、vllm、ollama、local、auto）、解析后的服务端基地址、认证凭据来源、默认模型标识、超时等可选参数。
- **对话请求上下文（Conversation Turn）**: 角色与内容组成的消息列表、温度、是否流式等调用选项（与现有接口一致）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 一名熟悉 README 的开发者能在 10 分钟内完成「从仅会 OpenAI 环境」到「切换为 ModelScope 或智谱」的配置并完成一次成功对话，无需查阅实现源码。
- **SC-002**: 在本地按文档启动 VLLM 或 Ollama 兼容服务后，开发者通过环境或构造函数仅改连接信息即可跑通现有示例脚本，业务代码中对 `think` 的调用形式不变。
- **SC-003**: 在仅设置 `LLM_BASE_URL`（含 `localhost` 与文档约定端口）与 `LLM_MODEL_ID` 的 Ollama 场景下，不显式传服务商时，90% 以上的试运行能在首次尝试推断正确服务商（以人工检查日志中服务商标签为准）。
- **SC-004**: 自动检测与显式 `provider` 冲突时，显式参数始终优先生效（100% 可重复验证）。
- **SC-005**: 继承扩展示例（教材中的 `MyLLM` 模式）在升级本仓库客户端后仍只需维护子类文件，不要求重新复制整个框架实现。
