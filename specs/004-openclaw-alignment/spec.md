# Feature Specification: 本地常驻个人助理（Agent Loop + 插件扩展 + OpenClaw 参照）

**Feature Branch**: `004-openclaw-alignment`  
**Created**: 2026-03-22  
**Status**: Draft  
**Input**: User description: "按个人需要重写规格：实现 agent loop；本地 7×24 运行；支持插件式扩展（tool / skills / MCP / subAgent 等）；并与 OpenClaw 能力方向对齐。"

**Reference product (non-binding)**: 仍以开源 OpenClaw 所代表的个人助理形态为参照（常驻控制面、通道、引导上线、安全默认值等）。本规格**优先锁定**用户明确提出的 **Agent Loop、7×24 本地运行、可扩展插件模型**；不绑定具体编程语言或供应商实现。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 主入口与可观测 Agent Loop (Priority: P1)

作为在本机部署助理的开发者或运营者，我希望通过**文档化的主启动方式**运行产品，并在一次或多次交互中完成目标；助理必须进入**稳定的「推理—行动—观察」循环**（或等价的显式循环语义）：在需要时调用已启用能力、根据结果决定下一步或结束，且全过程有**可读的进度与可追溯轨迹**。

**Why this priority**: 没有清晰的循环语义与轨迹，插件与常驻进程都无从验收；这是所有扩展能力的共同内核。

**Independent Test**: 在标准冒烟任务集上（含纯推理、单工具、多步工具链），确认循环在达到终止条件时结束，且轨迹覆盖关键步骤；人为中断或失败后行为符合文档（非静默卡死）。

**Acceptance Scenarios**:

1. **Given** 配置有效，**When** 操作者提交需要多步工具的任务，**Then** 助理按循环语义迭代直至 `Finish` 等价态，并输出最终答案或明确失败原因。
2. **Given** 某步工具超时或返回错误，**When** 循环继续，**Then** 助理在轨迹中记录该步，并向用户说明是否重试、换策略或终止。
3. **Given** 用户发起多轮对话，**When** 上下文在文档声明范围内延续，**Then** 后续轮次能引用前文意图，且每轮仍服从同一循环与轨迹规则。

---

### User Story 2 - 插件式扩展：Tool / Skill / MCP / SubAgent (Priority: P2)

作为希望扩展助理能力的贡献者或高级用户，我希望在**不修改核心内核代码**的前提下，通过约定方式注册：**原子工具（Tool）**、**技能包（Skill，含提示与工具组合元数据）**、**符合 MCP 约定的外部能力端点**、以及**可委派的子代理（SubAgent）**；并能为每一类扩展配置启用/禁用与权限级别。

**Why this priority**: 这是长期演进的扩展面；在 P1 闭环稳定后，应尽早固定**扩展契约**，避免后续插件生态推倒重来。

**Independent Test**: 各取一类最小示例插件（各 1 个），按文档完成注册后，主循环能发现并调用；禁用或撤下插件后，主循环不再暴露对应能力且不影响其他插件。

**Acceptance Scenarios**:

1. **Given** 已放置符合文档的 Tool 插件，**When** 主循环规划行动，**Then** 该工具出现在可选能力集中且调用结果进入轨迹。
2. **Given** 已注册 Skill 插件，**When** 用户意图匹配技能描述范围，**Then** 助理优先或按策略加载该技能的指令模板与关联工具集（行为以文档为准）。
3. **Given** 已配置至少一个 MCP 类端点，**When** 循环需要其暴露的能力，**Then** 调用经统一权限与超时策略，失败时在轨迹与用户可见输出中可区分「端点不可用」与「业务错误」。
4. **Given** 已注册 SubAgent 插件，**When** 主代理决策委派，**Then** 子任务在隔离上下文中运行，结果由主代理汇总；子代理**不得**默认获得超出其插件声明的权限。

---

### User Story 3 - 本地 7×24 常驻运行 (Priority: P2)

作为希望助理「一直在身边」的使用者，我希望产品在**单机本地**以**常驻进程/服务形态**运行，在无人值守时段仍能接收文档所支持的事件（例如定时任务、已连接通道消息）；在异常退出后具备**可文档化的恢复路径**（自动重启或受监督重启），且长时间运行下**资源增长在声明边界内**或可观测告警。

**Why this priority**: 与 OpenClaw「常驻网关」方向一致，且为用户显式目标；与 US2 可并行规划，但依赖 US1 的循环内核作为执行引擎。

**Independent Test**: 在规定的连续运行时长测试中，产品保持可用；注入可恢复故障后，在声明时间内恢复服务；内存/句柄等指标不超过文档阈值或触发可见告警。

**Acceptance Scenarios**:

1. **Given** 已完成安装与配置，**When** 操作者按文档启动常驻模式，**Then** 进程保持存活直至显式停止，且健康检查接口或等价自检返回正常。
2. **Given** 运行中发生可恢复错误（如外部 API 短暂不可用），**When** 超过重试阈值，**Then** 系统进入降级状态并记录原因，而非无提示崩溃；恢复后自动回到服务状态（若文档承诺自动恢复）。
3. **Given** 连续运行至少 **72 小时**（可分段累计的等价方案须在文档说明），**When** 周期性执行冒烟探针，**Then** **至少 99%** 的探针周期内响应成功，且无文档未说明的交互能力丧失。

---

### User Story 4 - 引导式上线与可维护配置 (Priority: P3)

作为首次部署者，我希望在分步指引下完成模型凭证、插件目录、MCP 端点、常驻选项与安全策略等配置；配置变更在重启或文档声明的热更新范围内生效，且误配时得到单一明确错误源。

**Why this priority**: 插件与常驻显著增加配置面；必须在规格上保证可重复上线。

**Independent Test**: 新环境按文档从零完成配置并启动常驻模式；故意引入冲突配置时启动失败并指向具体字段。

**Acceptance Scenarios**:

1. **Given** 缺少必选配置项，**When** 启动任意模式，**Then** 拒绝进入执行阶段并列出缺失项。
2. **Given** 修改插件启用列表或 MCP 端点，**When** 按文档触发重载或重启，**Then** 新能力集与文档一致。

---

### User Story 5 - 不可信入站与最小安全默认 (Priority: P3)

作为连接外部消息来源的使用者，我希望默认策略下未配对来源无法驱动高权限插件或 SubAgent；配对与权限变更可审计。

**Why this priority**: 常驻 + 插件放大攻击面；与 OpenClaw 安全叙事一致。

**Independent Test**: 模拟未配对入站请求敏感插件，100% 被策略拦截；配对后按文档放行。

**Acceptance Scenarios**:

1. **Given** 默认安全策略开启，**When** 未配对来源请求敏感能力，**Then** 不执行该能力并返回配对或授权指引。
2. **Given** 某插件声明为「高权限」，**When** 用户未在配置中显式授权，**Then** 主循环不得调用该插件。

---

### Edge Cases

- 两插件同名或同能力冲突时，解析顺序与报错行为是否唯一且文档化？
- MCP 端点半开连接、协议版本不匹配、工具列表变更时，主循环如何缓存与失效？
- SubAgent 递归委派或死循环：是否有限深、限时、限 token 预算的硬终止？
- 7×24 下日志与轨迹存储增长：是否可轮转、可配置保留策略，避免占满磁盘？
- 插件崩溃是否隔离（不影响主进程与其他插件），边界在哪里？
- 模型长时间不可用：常驻进程是否进入明确降级态并避免无限重试风暴？

## Requirements *(mandatory)*

### Assumptions & Scope

- **部署范围**：默认**单机本地**；多机高可用集群不在本规格范围（若未来扩展需另立规格）。
- **主启动入口**：产品 MUST 在文档中约定**唯一主入口**（可与历史文件名兼容，但以文档为准）。
- **MCP**：指行业通行的「用于向助理暴露工具的外部协议/约定」；具体版本集合以实现文档为准，但须在规格层承诺「可对接标准 MCP 形态端点」。
- **分阶段交付**：语音、画布、全量多通道 IM 等可继续分里程碑；**US1–US3 为本次愿景的核心验收带**，US4–US5 与核心并行规划但可按发布列车分期上线。
- **合规**：外部检索、消息通道与插件能力须遵守适用法律与平台政策。
- **默认 Tool 呈现**：`example-tool` 插件仅作 manifest 结构示例，**不向注册表注册任何工具**（历史上用于冒烟的 `echo` 已移除）。**仓库默认配置与 `WorkspaceConfig` 默认均不启用本地工作区**：未将 `workspace.enabled` 设为 `true` 并配置非空 `allowed_roots` 时，**不得**向模型注册 `local_workspace` 的三个工具。用户显式启用后，三个人类可读工具描述固定为：`workspace_list_dir` — 列出允许工作区内的目录内容；`workspace_read_file` — 读取允许工作区内的 UTF-8 文本文件；`workspace_write_file` — 写入或覆盖允许工作区内的 UTF-8 文本文件（具体参数模式以实现为准）。

### Functional Requirements

**核心循环与可观测性**

- **FR-001**: 产品 MUST 提供文档化的**主启动路径**，支持至少 **foreground（交互/单次任务）** 与 **常驻（守护/服务）** 两种运行模式（或等价子命令）。
- **FR-002**: 产品 MUST 实现**显式 Agent Loop 语义**（推理—行动—观察—直至终止），终止条件、最大迭代/预算须在配置或文档边界内可约束。
- **FR-003**: 产品 MUST 对每次用户目标生成**步骤级轨迹**（Thought / 工具或子代理调用 / 结果 / 最终答复 / 错误），并支持导出为人类可读或结构化格式；轨迹中 MUST NOT 默认包含密钥类秘密。
- **FR-004**: 产品 MUST 将模型与插件所需密钥、端点与策略与**业务代码分离**，通过配置加载；缺失必选项时 MUST 拒绝启动并提示。

**插件扩展**

- **FR-005**: 产品 MUST 支持 **Tool 插件**：声明名称、描述、参数模式、权限分级、超时；由注册中心在运行时发现或按文档静态注册。
- **FR-006**: 产品 MUST 支持 **Skill 插件**：至少包含人类可读说明、适用意图范围、以及对 Tool/子能力的绑定或引用关系；启用/禁用 MUST 不改变未关联技能的稳定性。
- **FR-007**: 产品 MUST 支持 **MCP 类能力接入**：将远端工具集映射进统一调用路径，并适用与 Tool 相同的权限、超时、轨迹与错误分类要求。
- **FR-008**: 产品 MUST 支持 **SubAgent 插件**：声明能力边界与可调用工具子集；主代理委派时 MUST 传递任务包与回传结构化结果； MUST 防止子代理默认越权。
- **FR-009**: 产品 SHOULD 提供**插件清单与版本/来源元数据**的加载与校验（缺失依赖时拒绝加载该插件并给出明确原因）。

**常驻与健康**

- **FR-010**: 在常驻模式下，产品 MUST 提供**健康检查**（人或机器可读），覆盖配置加载、主循环存活、关键依赖连通性的子集（具体项文档列举）。
- **FR-011**: 产品 MUST 文档化**崩溃与可恢复故障**后的行为（例如监督进程重启、指数退避重试上限）；禁止无限 tight loop 重试无退避。
- **FR-012**: 产品 SHOULD 支持**受控关停**（优雅停止处理中任务或声明中断策略），避免强制杀进程为唯一方式。

**配置、自检与安全**

- **FR-013**: 产品 MUST 提供**首次上线文档**（可与向导组合），覆盖：主入口、常驻启动、最小插件启用、冒烟任务、常见问题。
- **FR-014**: 产品 MUST 提供**自检入口**（命令或模式），帮助区分配置错误、外部依赖故障与内部缺陷。
- **FR-015**: 对入站消息驱动路径，产品 MUST 默认启用**不可信来源策略**（配对/授权/忽略）；敏感插件 MUST 仅在显式授权后对给定来源可用。

### Key Entities *(include if feature involves data)*

- **会话 (Conversation)**：多轮用户—助理交互，含循环状态与对插件可见的上下文切片策略。
- **Agent Loop 运行 (Run)**：一次从用户目标到终止的执行实例，含迭代计数与预算消耗。
- **工具 (Tool)**：原子可调用单元，含权限与超时。
- **技能 (Skill)**：面向意图打包的指令与工具编排元数据。
- **MCP 端点 (MCP Endpoint)**：外部能力提供方逻辑连接，含端点身份与健康状态。
- **子代理 (SubAgent)**：被委派的独立推理主体，含能力白名单与生命周期。
- **插件包 (Plugin Package)**：装载 Tool/Skill/SubAgent 或 MCP 客户端配置的发布单元（逻辑实体）。
- **配置档案 (Configuration Profile)**：模型、常驻、插件、安全策略的统一配置视图。
- **轨迹 (Trace)**：可导出的步骤记录，用于审计与排障。
- **入站来源 (Inbound Source)**：通道内发送方标识，用于配对与授权。
- **健康快照 (Health Snapshot)**：某时刻服务是否可接受新工作的判定材料。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 新工程人员在仅依赖文档情况下，**60 分钟内**完成首次启动（foreground），并跑通不少于 **4** 个冒烟场景（纯推理、单工具、多步工具、多轮对话各至少 1）。
- **SC-002**: 在受控任务集中，**至少 90%** 的需工具任务得到**任务完成型**结局（明确答案或明确不可行），且轨迹中可找到对应工具步骤。
- **SC-003**: 各类型插件（Tool / Skill / MCP / SubAgent）各至少 **1** 个参考插件，按文档注册后 **100%** 可被主循环正确加载与调用（或按文档预期拒绝并给出原因）。
- **SC-004**: 常驻模式下 **72 小时**稳定性测试中，周期性探针成功率 **≥ 99%**，且内存占用不超过文档声明上限；若超限须有可见告警或自动保护动作。
- **SC-005**: 注入可恢复外部故障时，**100%** 案例在文档承诺时间内进入**可识别的降级或恢复态**（非静默崩溃且无轨迹）。
- **SC-006**: 未配对入站样本中 **100%** 无法触发敏感插件；错误配对尝试可被审计轨迹或日志捕获（抽样 ≥ 10 组）。
- **SC-007**: 支持人员 **20 分钟内**使用自检输出区分 **配置错误 / 插件或 MCP 端点故障 / 模型或网络故障 / 内核缺陷** 中的至少 **三类**。

---

## Out of Scope（明确不包含）

- 多租户 SaaS 化与云端控制面（除非另立规格）。
- 具体即时通讯商业 API 的全量对接（可在后续通道规格中展开）。
- 保证任意第三方插件代码安全无虞（规格要求**权限模型与隔离边界**；恶意代码防护依赖 OS 与部署实践，不在此承诺无限安全）。
